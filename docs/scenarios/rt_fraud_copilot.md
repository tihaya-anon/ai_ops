# 场景文档（主场景）：实时交易/支付风控分流与处置 Copilot

> 目标：选择一个“对实时性要求很高”的场景，但仍能**合理使用** Kafka/Flink +（可选 LLM/RAG）+ 观测与韧性能力。

---

## 1) 为什么不直接做“量化交易下单用 LLM”

量化交易里**最硬实时**的链路（行情->策略->下单）往往要求毫秒甚至更低延迟：

- LLM 推理（即便 vLLM）通常做不到稳定的 ms 级端到端
- LLM 放在下单关键路径会让风险不可控（不确定性、输出不稳定）

所以更合适的切入是：

**把“硬实时的风控决策”留给 Flink/规则/轻量模型；把 LLM 用在“解释、归因、处置建议、案件总结”上，且不进入关键拦截路径。**

这能同时满足：

- 真实业务的实时性与稳定性要求
- 你想展示的流处理/数据平台/可观测/韧性/LLMOps 能力

---

## 2) 业务问题与实时性要求（明确 SLO）

### 2.1 业务问题

对交易/支付平台来说，核心目标是：

- 在“欺诈/羊毛/盗刷/撞库/套现”等风险发生时，**实时拦截**或**实时升级审核**
- 同时尽量降低误杀（误拦正常用户）与审核成本

### 2.2 实时性 SLO（建议）

- **决策链路（硬实时）**：交易进入 -> 风险评分/规则 -> 放行/拦截/升级审核：p95 ≤ 100ms（本地练习可用秒级模拟，但设计上要有这个预算）
- **解释链路（软实时）**：生成“为什么拦截/建议补充信息/案件摘要”：p95 ≤ 5s（允许异步）
- **回放/纠偏（离线）**：每天重算特征、回填标签、输出评估指标：T+1

这正好对应 Lambda 风格：

- Speed layer：硬实时决策
- Batch layer：离线纠偏与评估
- Serving layer：对外查询与审计

---

## 3) 端到端链路（详细到可实现）

### 3.1 数据输入（Kafka 事件流）

核心主题示例：

- `tx_events`：交易/支付事件（金额、商户、设备指纹、IP、地域、渠道、用户画像摘要等）
- `auth_events`：登录/鉴权事件（失败次数、异常地登录、设备变更）
- `chargeback_events`：拒付/申诉（用于后验标签）
- `policy_docs`：风控策略/合规条款/审核 SOP 文档变更（用于 RAG）
- `risk_outcomes`：最终处置结果（放行/拦截/人工判定，作为监督信号）

### 3.2 Speed layer（Flink）：实时特征 + 决策分流

Flink Job 做：

- 近 N 分钟窗口：同一用户/设备/IP 的交易频次、失败率、金额突增
- join 维表：黑名单、商户风险等级（本机可用本地 KV/定期拉取）
- 输出：
  - `risk_decisions`：实时决策（allow / block / review）+ 核心证据字段（特征值）
  - `risk_cases`：需要人工/进一步解释的 case（进入后续 Copilot）

关键点：**这里不依赖 LLM**，保证确定性与延迟。

### 3.3 Copilot layer（异步）：LLM/RAG 生成“可审计的解释与处置建议”

对进入 `risk_cases` 的事件，做：

1. RAG 检索（证据）
   - 检索风控策略/合规条款/审核 SOP
   - 检索历史相似 case 与结论（如果你有模拟数据集）
2. LLM 生成结构化输出（不胡编）
   - **必须结构化 JSON**：`case_summary`、`why_flagged`、`suggested_next_steps`、`required_evidence`、`citations`
   - `citations` 指向具体文档 chunk 或规则 id（可追溯）
3. 写入 Serving（Postgres/ES），同时推送到审核队列（IM/工单/简易 UI）

### 3.4 Batch layer（Spark）：离线纠偏、可复现评估、回放

Spark 每日/每小时批任务适合做：

- **特征与决策回放**：对昨天数据按新规则重跑，验证误杀率/漏报率变化
- **指标与报表**：按商户/渠道/地域输出风险分布与趋势
- **训练/评估数据集**：从 `risk_outcomes` 生成 label，构建可复现评测集（RAG 命中率、case 解释一致性等）

---

## 4) 验收标准（个人项目也能“像生产”）

- 决策链路：事件进入 Kafka -> Flink 输出 `risk_decisions`（本地压测下 p95 延迟可观测）
- 解释链路：`risk_cases` ->（RAG+LLM）-> 产出结构化解释（含 citations）
- 可观测：每个 case 有 `trace_id`，能看到 Flink/RAG/LLM/Serving 的耗时与失败率
- 可回放：Spark 能按 `dt=YYYY-MM-DD` 输出离线聚合与评估指标（可复现）
