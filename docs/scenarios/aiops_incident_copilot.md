# 场景文档：实时 AIOps 事件分流与处置 Copilot（面向生产运维）

> 这份文档是一个备选场景（很适合 Kafka/Flink + RAG + OTel + Chaos），但“硬实时”强度通常低于交易/风控类场景。

## 为什么适配这套技术栈

这个场景的核心不是“做一个会聊天的运维机器人”，而是把 **生产运维的事件流**（告警、日志、变更、工单）做成一个 **实时 AI 数据系统**：

- **天然是流式数据**：告警/日志/Trace 是持续不断的事件流，且高并发、高峰值，适合 Kafka 作为总线、Flink 做实时处理。
- **强时效**：MTTA/MTTR 直接影响业务损失，要求分钟甚至秒级的分流与归因；离线跑索引/手工查资料不够。
- **知识持续变化**：Runbook、SOP、架构拓扑、事故复盘都在变；需要“实时更新的 RAG”，而不是每天离线重建。
- **需要生产级可观测**：一次“AI 误判”会带来错误处置；必须能用 OTel 追踪每一步耗时/命中证据/模型调用。
- **必须具备韧性与降级**：模型挂了、向量库慢了、外部依赖超时都不能拖垮告警链路；Chaos 与降级路径是必需品。

## 端到端链路（概览）

1. 数据源（监控/日志/APM/变更/工单）-> Kafka
2. Flink 窗口聚合/去重/关联 -> 生成 `incident_candidate`
3. RAG 检索 runbook/相似事故 -> Evidence Pack
4. LLM（可选）生成结构化建议 -> 输出到工单/IM
5. 处置结果回流 -> offline 评估/规则迭代/文档更新
